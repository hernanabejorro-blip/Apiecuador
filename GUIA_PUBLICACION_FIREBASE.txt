PUBLICACIÓN SEGURA DE APIECUADOR EN FIREBASE HOSTING

Estado
- .firebaserc apunta al proyecto existente apiecuador-34b2d.
- GitHub Pages se conserva como respaldo; este flujo no la elimina ni la modifica.
- La publicación es manual y está aislada en la rama preparar-publicacion-firebase.
- El primer despliegue va al canal temporal "prueba-api-ecuador" (7 días), NO al canal público live.
- Este flujo no modifica reglas de Firestore ni documentos de la base de datos.
- La autenticación prevista es OIDC / Workload Identity Federation; no requiere una clave JSON permanente.

Configuración de Google Cloud necesaria (una sola vez)
1. La cuenta de servicio dedicada ya creada es:
   apiecuador-github-deploy@apiecuador-34b2d.iam.gserviceaccount.com
2. Concede a esa cuenta solo el rol necesario para publicar en Firebase Hosting. No le concedas Owner, Editor ni acceso a Firestore.
3. Configura Workload Identity Federation para GitHub Actions en el proyecto Google Cloud:
   - Crea un Workload Identity Pool.
   - Añade un proveedor OIDC con issuer https://token.actions.githubusercontent.com.
   - Restringe la confianza al repositorio hernanabejorro-blip/Apiecuador y a la rama preparar-publicacion-firebase; no aceptes cualquier repositorio o rama.
   - Permite que el principal federado correspondiente a ese repositorio/rama actúe como la cuenta de servicio anterior mediante roles/iam.workloadIdentityUser.
   - Copia el nombre completo del proveedor, con formato projects/PROJECT_NUMBER/locations/global/workloadIdentityPools/POOL_ID/providers/PROVIDER_ID.
4. En GitHub > Settings > Secrets and variables > Actions > Repository secrets, crea:
   GCP_WORKLOAD_IDENTITY_PROVIDER
   Valor: el nombre completo del proveedor OIDC del paso anterior. No es una clave privada.

Antes de ejecutar
5. Comprueba que exista un sitio de Firebase Hosting para el proyecto. Si solo aparece la guía de CLI, primero hay que terminar de inicializar Hosting.
6. La acción workflow_dispatch debe estar disponible desde la rama predeterminada para aparecer de forma fiable en Actions. Revisa el PR de preparación antes de integrarlo; no publiques al canal live.
7. Cuando esté disponible y el secreto esté configurado, ve a Actions > "Publicar ApiEcuador en Firebase Hosting" y ejecuta desde la rama preparar-publicacion-firebase.

Precauciones
- El flujo publica solo al canal temporal "prueba-api-ecuador", que expira en 7 días.
- No se configura publicación automática al canal live.
- Si falta el proveedor OIDC, el sitio de Hosting o los permisos, el despliegue fallará sin tocar Firestore.
- Antes de una futura publicación live, prueba el sitio y revisa explícitamente el contenido servido desde la raíz del repositorio.
- No generes claves JSON ni las compartas por chat.
